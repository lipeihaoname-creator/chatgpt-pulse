# 数据与隐私

## 支持范围

Pulse 读取本机 Work / Codex 的兼容 JSONL 事件与用量日志。自动发现使用当前用户主目录下的 `.codex/sessions`，可用进程环境中的绝对 `CODEX_HOME` 覆盖根目录。它不识别前台聊天归属，也不监测普通 ChatGPT 或浏览器聊天。没有兼容日志时保持不可获取。

## 工作状态

状态依据任务开始、完成、中止，以及推理、回复、工具调用/结果等白名单事件元数据。工具结果按调用标识匹配，不依赖聊天内容猜测。批准或提问只在日志明确提供相应事件时显示；客户端未写入时无法获取。

30 秒无新活动表示“状态待确认”，不能判定卡死或空闲。每秒检查只说明采样器仍在运行，不表示模型每秒都会写入用量。最近活动轨迹最多 12 条，只存内存。多个任务分别绑定日志；一个头像可以显示多个任务气泡，不代表所有聊天窗口都被覆盖。

## Token 计数

读取 `token_count` 的输出与推理累计用量，任务计数取同一日志中任务前后的差值。相同累计更新不重复相加。缺少开始前基线时，任务计数保持未知；概览和启用了累计显示的气泡明确展示“会话累计输出”。它是日志原值，不是本轮任务计数，详情仍保留两种口径。

推理用量已包含在输出中，不能再相加；也不能用减法声称得到了精确可见正文 Token 数。发生累计重置、日志损坏或截断时停止推断。不会从字符数估算 Token。

## Token/s

显示的是新增输出计数除以上报区间时长，采用日志时间戳。有任务前累计基线时，首段从任务开始计时；没有该基线时，首次累计上报只建立区间起点，从下一次有效递增上报开始计算两次记录之间的速率，整轮任务计数仍保持未知。区间不足 100 毫秒时只保留计数，避免批量落盘产生的毫秒级尖峰。它不是服务器实时解码速度。

新用量到来前保持上次区间数值，5 秒后注明“上次报告”和年龄。仍有推理、回复或工具活动时可继续保留；连续无活动达到设定期限后隐藏，默认 30 秒，自动适应模式可按上报节奏延长。重复用量不会延长有效期。保留值不代表当前速度，未上报也不能当作 0；明确结束或中止后速率归零。

最终任务均速单独展示，仅用匹配的任务开始/结束标识与日志明确提供的耗时计算，包含推理、工具和等待。缺少有效数据时显示 `—`。后台实际模型、服务器负载、首字延迟及可见正文精确 Token 数不在可获取数据中。

## 本地保存

日志逐行临时解析，只传出白名单中的计数、时间与任务标识；不会保存聊天、输入、推理正文、工具参数或工具结果，也不读取认证信息、窗口标题或屏幕内容。没有额外 AI 或收费 API 请求，不上传指标。

SQLite 默认仅保存设置，包括用户主动设置的任务昵称与图片裁剪；启用记录后才保存监测期间新结束任务的数字摘要与去重标识。自定义图片保存在本机。关闭记录不等于自动删除已有记录，可在记录页明确清空。不会导入历史聊天正文。

设置、图片及可选记录使用系统应用数据目录。Mac 为 `~/Library/Application Support/io.github.chatgptpulse.desktop`；Windows 为当前用户的 `%APPDATA%/io.github.chatgptpulse.desktop`。Windows 本机验证范围与应用容器映射说明见 [Windows 验收报告](WINDOWS_ACCEPTANCE.md)。
