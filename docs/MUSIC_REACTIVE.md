# macOS 音乐律动（本地开发候选）

尚未发布到 GitHub Release。生产输入来自系统播放音频，不是音乐分类器；语音、视频、游戏也会响应，不识别曲名、歌词或情绪。

## 开启

侧栏 → 音乐律动 → 响应系统播放音频。默认关闭；第一次启动采集时由 macOS 请求系统音频录制权限。不会访问麦克风，不需要辅助功能、全磁盘或屏幕录制权限，不安装虚拟声卡。拒绝或撤销授权后检查系统设置的隐私与安全性 → 屏幕与系统音频录制（具体名称随系统版本变化），然后回到 Pulse 重试；不自动修改系统权限。

开启偏好保存在原设置 JSON 中，不变更 SQLite 表或清空数据。重启后按保存的开启偏好重新尝试连接，仍由 macOS 核实当前系统音频权限；偏好本身不授予权限。授权失败时停止并显示“启动 / 重试音频”，不循环申请或修改系统隐私设置。关闭开关会停止后台采集并释放 tap、IOProc、私有聚合设备及内存缓冲。

macOS 14.2+ 使用 Core Audio Process Taps。13.3–14.1 仅提示不支持音乐功能，保留其他功能与最低 macOS 13.3 要求；本轮没有引入需要屏幕录制权限的 ScreenCaptureKit 回退。没有付费 API、额外 AI、常驻音频服务或外部运行时。

## 显示与动作

- 默认底部横条，24 个对数分布频段。头像模式的横条贴近头像底部；半环与头像同心，内缘距头像约 2px。工作粒子出现时，仅频谱平滑移入粒子下方的紧凑区域，保留粒子节点、轨迹、大小与透明度。附加窗口高度从 40px 缩小为 16px；频谱样式和工作状态切换不改变窗口高度或头像位置。
- 音乐从偏好设置独立为侧栏页面，分为系统音频、频谱、人物三组；废弃的星光/星环/柔光工作指示已从界面和头像移除。旧 motion 字段仅作旧设置兼容，不再渲染。
- 频谱只表现实际分析结果；约 25Hz 音频特征通过最多约 60Hz 的视觉帧平滑衔接，快速抬升、柔和回落，并附短暂峰值点。横条与半环在当前形状之间过渡，不重建窗口；峰值仅是内存中的短时视觉包络。无输入/停止播放后衰减并淡出，失去新数据时隐藏，不用随机数生成柱高。颜色沿用主题，装饰不接收指针事件。
- 修正首次打开时必须先完成一次任务才能律动的限制：启动约 2 秒后，成功完成新的日志扫描，且扫描范围内没有未结束任务、加载中、不完整或不可读取的记录，即可响应音乐；空目录或旧的已完成任务也可。扫描依据只授权装饰性音乐动作，不改变“未收到任务信号”等工作状态，也不声称能够知道未写入日志的 GPT 活动。暂停监测、速率为零、日志静默均不是任务结束依据。多任务逐项检查，不能只看主头像状态。
- 真实工作、用户互动、当前对话、原有空闲动作均优先于音乐动作。原有姿态、呼吸、眨眼层保留；音乐只在独立附加姿态层小幅平移和旋转，不缩放头像，不切换工作表情。任务开始即停止节拍驱动，并从当前姿态平滑回正。
- 律动使用持续相位、音量包络和柔和点头，不在每个节拍重启关键帧。进入时从当前姿态渐入，打断时回正；麻衣幅度较克制、洛琪希略活跃，长时间播放时缓慢混合动作变化，不改变头像大小。重连、节拍计数重置、恢复显示后不补播旧节拍。
- 减少动态效果、关闭角色动效、关闭音乐人物律动、勿扰、拖动和渐隐时不启动音乐身体动作。音乐人物律动与普通空闲表情动作开关独立；系统减少动态效果、角色动效或勿扰阻止律动时，音乐页明确显示原因。减少动态效果时频谱约每秒更新 5 次、关闭峰值点；原生窗口隐藏时停止绘制，工作状态下音乐姿态回正后不再逐包写入变换。macOS 的 WebKit 可能将失焦但可见的悬浮窗标为 hidden；音频帧携带原生窗口可见性，遇到这种情况使用有限频率计时绘制，避免误停。窗口真正隐藏时立即发布可见性状态并清理绘制任务，浏览器预览仍尊重网页可见性。自定义头像保留自身裁剪，不被音乐逻辑改写。
- 两名角色各有 12 组、每组 3 句原创音乐话题，约 65% 权重进入原有空闲话题选择，稳定音乐中的首次自动话题优先使用音乐组；稳定音频至少 3 秒才进入候选池。共用原有对话调度器、连续回复、勿扰和主动对话开关。音乐活跃时的随机间隔：安静 90–240 秒、偶尔 45–105 秒、活泼 22–55 秒；音乐停止后恢复普通空闲间隔，没有独立新增说话定时器。悬浮窗可见但 WebKit hidden 时也会计时；读取异常、工作任务和真正隐藏仍阻止自动对话。

## 实现与隐私

Objective-C 原生桥接只在后台创建私有 tap/聚合设备。实时音频回调不分配、不加锁、不调用 IPC，只写入 32768 个 float 的固定容量 SPSC 缓冲；满时丢弃新样本，不扩大内存。读取后擦除已读区。支持 float32 系统音频，对不支持格式明确报错，避免错误解释内存。

Rust 后台使用 2048 点 Hann 窗 FFT，计算 RMS、低/中/高频能量、24 段频谱、攻击/释放平滑、低频瞬态阈值及最短节拍间隔。节拍是简单音频瞬态估计，不是精确 BPM。分析约 25Hz，频谱帧仅发往悬浮窗口；主设置页最多约 1Hz 更新状态。窗口隐藏时不发送连续频谱事件。原始音频与频谱均不写文件或数据库，不上传，不生成可还原的音频历史。

设备切换/采样率变化以及较长休眠间断后释放旧资源再重连。启动失败或没有回调时停止并提供用户重试入口，避免循环弹授权。某些系统权限状态可能表现为零缓冲；静音提示不等同于证明授权成功，播放时始终无响应应检查权限。

## 验证记录

首轮音乐功能已通过 62 项前端逻辑测试、114 项 Rust 测试（另 2 项真实本地输入检查默认忽略）、28 套完整生产界面回归，并在最终设置调整后补跑音乐和设置两套。原生固定缓冲测试通过。

本机 macOS 27.0.1 Apple Silicon 已通过真实 Core Audio 采集：使用合成 PCM 经 macOS 系统输出播放，实际驱动原生频谱；这是系统采集测试，不是向前端注入频谱。此前隔离工作日志验证工作时不律动、完成后允许律动、新并行任务立即阻止、播放停止后无残留；首次等待的准入规则在本轮进一步修正，以下以最新验证记录为准。原生四任务独立/合并气泡均通过；原生头像频谱截图保留在本地。通用二进制包含 arm64/x86_64，两架构最低 macOS 均为 13.3，14.2 的 tap 函数采用弱链接。

上一轮平滑优化通过 68 项前端逻辑测试与 28 套完整生产界面回归，覆盖不同刷新率、范围、形状切换、打断回正、旧节拍与计数重置。界面用隔离合成特征检查逐帧插值、减少动态效果更新上限、隐藏停绘和工作时姿态停止写入；它们不能替代原生采集测试。优化后的最终通用候选再次通过 6 项原生系统音频检查，包含保存偏好自动恢复、并行工作打断、全部完成恢复及播放停止收势。最终候选结果另见本地 `release/MUSIC_SMOOTH_VALIDATION.json`；上一轮后端测试结果不冒充本轮重测。本轮没有重做资源基准，不能据此声称整体 CPU 降低。

紧凑布局与首次等待修复的最新验证见 `release/MUSIC_COMPACT_VALIDATION.json`。纯逻辑新增几何避让与原生可见性检查，总计 70 项前端测试通过；本轮 Rust 回归 115 项通过，另 2 项真实个人日志检查默认忽略。最终 Mac 通用候选通过 9 项原生音频检查，新增“无须先完成任务即可随音乐动”和“WebKit 报 hidden 时，可见原生悬浮窗仍实际改变人物姿态”，并验证任务/并行工作打断和静音收势。测试只用合成节奏经系统输出播放及隔离日志；采集就绪后先检查系统音频基线，再开始播放，避免混淆启动过程、其他音源与静音。测试来源和未验证边界逐项记录。

首轮完整结果见本地 `test-results/music-validation.json`。合成 PCM 测试与界面隔离夹具只验证算法/交互，不能替代真实 Mac 授权采集。Intel 实机、macOS 13.3/14.1/14.2、蓝牙设备拔插、撤销权限及睡眠唤醒需要分别标记，不能由本机运行代替。

## 开发依据

- [Apple：Core Audio taps 示例](https://developer.apple.com/documentation/coreaudio/capturing-system-audio-with-core-audio-taps)：tap、私有聚合设备、生命周期及录制授权。示例工程的当前工具链要求不等于 API 自身首次可用版本；本轮同时检查本机 SDK 的 14.2 availability 声明。
- [Apple：NSAudioCaptureUsageDescription](https://developer.apple.com/documentation/bundleresources/information-property-list/nsaudiocaptureusagedescription)：权限说明键。
- [Apple：ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)：旧系统回退调研；本轮未启用。
- [麻衣声优官方访谈](https://ao-buta.com/tv/special/interview/seto.html)：克制、看似强势但会害羞的表达；采用关心与轻微调侃。
- [洛琪希官方角色介绍](https://mushokutensei.jp/character/)与[声优寄语](https://mushokutensei.jp/staff-cast/)：认真温和的教师、偶尔迷糊的反差。

话题均为原创中文同人互动，不是原作台词或歌曲歌词。沿用已有表情素材，没有新增或冒充 Live2D/逐帧面部动画。

## 实机画面与资源观察

![原生工作状态、保留粒子及真实系统音频频谱；工作日志为隔离模拟](media/music-reactive-working-macos.png)

本机主进程短时观察（各约 10 秒，不含 WebKit 子进程）：日常 0.16.6 的隔离单任务基线 CPU 约 7.59%、RSS 约 151 MiB；音乐候选在隐藏主窗口、关闭音乐时约 2.70% / 115–131 MiB，开启合成系统音频时约 8.03% / 124 MiB。不同场景不构成严格前后对照，也不能据此宣称整体内存降低。

最终同一候选进程、主设置与悬浮窗均显示时：开启音频并播放合成音 CPU 约 11.58%、RSS 约 126 MiB；关闭后约 8.91%、RSS 约 125 MiB。关闭后采集状态已在原生界面确认；这仍是短时、单机观察，缺少长期稳定性和完整 WebKit 进程测量，后续应继续优化并长测。

保存的开启偏好自动恢复已在最终通用候选包上实测通过，没有调用手动启动命令；可复现测试为 `PULSE_APP="/path/ChatGPT Pulse.app" python3 tests/music-native.py --system-audio-confirmed`。测试只使用合成播放输入和隔离任务日志，音频权限仍由 macOS 决定。

## 0.17.0 交互整改

- 贴边收纳后悬停不再展开气泡，点击头像才打开互动；真实工作和需操作状态仍按原策略显示。
- 首个气泡用实际高度与头像中心对齐，内容变长、左右贴边、多个气泡时持续更新；多任务窗口补足下方空间。
- 频谱加粗、略提高对比和幅度；保留工作粒子与透传区域。
- 人物使用三组每周期 12 个动作关键点，在闭合曲线间平滑衔接；不新增整张头像替换。声音较轻但确实活跃时保留小幅可见律动，不用该幅度表示音量数值。
- 原生可见性判断同时用于空闲对话和表情过渡，避免失焦时停止话题或硬切表情。

本地验证结果见 `release/INTERACTION_VALIDATION.json`。本轮未增加 AI 生成位图；动画关键点由代码生成，沿用已校准的人物图集与固定头发、衣服轮廓。安装包、旧版清理和保留数据范围见本地交付记录。

本轮最终验证：73 项前端逻辑、115 项 Rust 测试（另 2 项个人日志检查忽略）、28 套完整生产界面回归通过。Mac 通用候选通过 10 项真实系统音频场景（包含实际等待随机期限后的主动音乐对话），四任务独立/合并原生气泡各通过验收。本轮 WebKit 在原生姿态观察时报告 visible；hidden 分支由界面强制夹具验证，不将它记作本轮原生 hidden 实测。

## 0.17.2 Mac 自检整改

- 下半环按椭圆弧长均匀布置 24 个频段，采用曲面法线向外伸缩；保持真实频段顺序与原有纵向幅度。工作状态压扁为下方小弧线时，相邻中心至少间隔 3.7 个逻辑像素，2.6px 圆头笔画不会在两端合并。柱状样式、头像内缘和粒子轨迹不变。布局在稳态缓存，频谱与峰值标记共用。

- 自检包含 Node/Rust 全量逻辑、完整生产界面回归、Core Audio 缓冲/格式检查及隔离日志的原生验收。最终实际结果和未覆盖项记录在 release/MAC_FINAL_VALIDATION.json。测试音频为本机内存处理，不保存采集数据；合成播放输入与真实工作日志隔离。尚未发布 GitHub。
