# Mac 音频冷启动修复 · 0.18.3

2026-10-30。用户报告恢复已开启的音乐设置后，界面显示静音但已有系统音频，切换开关才恢复。旧版的四轮本机启动没有稳定重现该偶发状态，因此不把普通启动通过当作问题不存在。

## 处理

- Core Audio 创建私有聚合设备是异步过程；后台等待 IsAlive，最长约 2 秒，然后才注册并启动 IO。超时会提示并有限重试，不阻塞界面线程。
- Mac 新采集生命周期从未收到非零 PCM 时，允许在连接 2 秒后最多完整重建两次 tap/aggregate。停止会在原工作线程释放对象。两次后仍零则保持真实静音，不无限循环、不制造频谱、不推断权限或播放内容。
- 一旦收到真实非零 PCM，本生命周期不再因为静音重连；65 秒静音与恢复单独验收。权限拒绝不会进入自动授权循环；关闭开关或退出可以取消恢复。
- 保留仅 tap 的采集组成，不加入物理音频设备的输入，不引入麦克风采集。Windows WASAPI 路径不采用本次 Mac 零 PCM 恢复策略。

## 验证

本机 126 项 Rust 测试通过，2 项显式真实输入用例默认忽略；84 项前端、29 套完整界面回归通过。四次原生故障注入把首次 native stream 的 PCM 置零，同时保留健康回调；程序无需手动切换就恢复真实系统音频和人物律动。六次普通冷启动覆盖先播放再启动，以及启动后延迟播放。它们不保证所有测试间隔的整机音频均静音。

实际原生验收还包括音频关闭释放、重新开启、隐藏/最小化/还原、正常退出、工作优先级、65 秒真实静音和恢复、随机音乐对话。故障注入仅同时启用三个隔离测试标记时可用，普通用户会话不启用。完整结果随 Mac 发布资产的验证清单提供。

就绪等待依据 Core Audio 设备属性；全零启动恢复是对报告症状的有界防护，不代表能可靠区分所有驱动故障与正常静音。Intel/其他 Mac、蓝牙/USB 实物切换和首次权限弹窗的人工操作仍未在本轮完成验收。
