## 合并与保留

合并 Windows-only `wasapi.rs`、`audio_format.rs`、对应目标依赖、音频 Result/ReadResult 接口、设备恢复/静音规则及最小化可见性。共用 UI 使用实际平台支持状态，保持原有六种样式、方案、条带对比度、人物音乐话题及工作/交互优先级。

Mac 的 `system_audio.m`、Info.plist、macOS 最低版本/权限配置、音乐候选身份、启动项关联、源码白名单、DMG 校验和去重打包修复全部保留。Windows 交付中的较旧 Mac 包装、依赖说明、CI 与窗口测试高度没有覆盖本机版本。现有日志、单实例、存储、Windows 安装工具以及根 LICENSE、第三方通知、许可库存逐字节相同，未改用旧版本。

本轮原生验收发现周期采样会重新显示已被用户最小化的悬浮窗；已改为尊重原生最小化状态，仅用户明确重新显示时还原。四种可见/最小化组合有单元测试，真实最小化、等待、检查和还原均重新通过。该共用窗口修复尚未在 Windows 重新构建，不把原 Windows 安装器当作包含此修复。

Mac 退出事件线程不直接等待采集线程：采集可能仍在向界面线程查询窗口状态，直接 join 有阻塞风险。Mac 保持先发停止信号；设置关闭仍在后台串行 join/销毁旧流。Windows 路径保留交付时的线程等待逻辑。

测试侧保留高刷新率按经过时间采样、CSP 直接读相同生产 HTML，以及可选无网络资源路由；Mac 正常本机 HTTP 生产回归单独执行，不把 Windows 环境中的网络限制当产品缺陷。

## 本轮验证及边界

前端逻辑、Rust、完整生产界面、本机原生音频和窗口生命周期的实际结果由候选目录 `MAC_MERGED_VALIDATION.json` 和随附验收证据记录。历史 Mac 报告及 Windows 的 83/123/29 项结果不充作本轮 Mac 结果。

本轮最终结果：84 项前端测试通过；124 项 Rust 测试通过，2 项需要显式真实输入的用例忽略；29 套生产界面完整回归通过。两种 Mac 架构各 241 个第三方依赖均在原许可库存内；原生音频环形缓冲检查通过。最终通用应用通过 6 组原生回归：音频开关/释放与隐藏/最小化/正常退出、65 秒真实静音及恢复/随机音乐对话、四任务独立气泡、四任务合并气泡、30 秒无焦点后台监测及巨大工具结果、贴边双重启恢复。音乐窗口为 280×144 逻辑像素（原 128 加 16），工作多任务为 280×318/362。系统音频回归没有跳过，但本轮未观察到 WebKit 自报 hidden 的特殊失焦分支；该分支只由界面夹具覆盖。

首轮界面回归曾有 3 项失败：一次与并行构建写 dist 冲突，一次等待布局稳定不足，一次交互等待超时。保留原失败记录，修正测试布局等待并停止并行构建后，最终完整 29 套重新通过；没有把失败直接改为成功。最小化缺陷也保留原失败记录并以修复后的最终应用复测。

原生测试只使用隔离数字日志、用户已同意的系统音频采集和生成的播放输入。测试控制文件仅在三个显式测试环境标记同时启用时使用，不能在普通用户会话运行；命令固定为开关、隐藏/显示及最小化/还原，不执行任意脚本或接受外部路径。

Mac 通用构建含 arm64/x86_64，仅本机 Apple Silicon 运行；Intel 实机、异机、蓝牙/耳机实物切换、多显示器及所有睡眠/设备组合尚未验证。Mac 音乐候选仍为 `io.github.chatgptpulse.musicpreview`；早期 `io.github.chatgptpulse.desktop` 的数据及系统许可迁移未验证，公开身份和升级方案仍需审阅。Windows 安装器保持交付时原字节，不声称由 Mac 重新构建；当前合并源码没有在 Windows 再构建，详细 Windows 测试边界见原交付报告。

Windows 混音使用多声道均值，Mac 使用主导声道；特殊反相声源的视觉差异未做 Windows 实机验证。短时单机资源结果不能证明长期无泄漏或所有机器性能。
